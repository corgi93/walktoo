# QA 가이드

walkToo 변경사항 검증·회귀·릴리즈 전 체크 시 핵심 룰. 공통 룰은 `AGENTS.md`를 따른다.

## 필수 게이트

- `npx tsc --noEmit` 통과
- `pnpm lint` 통과
- 위 두 가지가 실패한 채로 "검증 완료"라고 보고하지 않는다.

## 빌드·런타임 영향

- Native module 변경 여부 확인. 있으면 **iOS/Android dev client 재빌드 필요**를 결과에 명시한다.
- Expo Go에서 동작하지 않는 변경은 그 사실을 분리해 보고한다.

## 기능 회귀 체크

- **커플 핵심 루프**: 각자 기록 → 둘 다 완성 → 공개 흐름이 깨지지 않는가.
- **지도/장소**: SDK 키가 없는 환경에서도 검색-only + 텍스트 입력 fallback이 동작하는가.
- **걸음수 동기화**: `docs/step-sync.md`의 60s 배치 / 30s polling이 유지되는가.
- **결제(IAP)**: RevenueCat 샌드박스에서 한쪽 결제 → 둘 다 혜택 시나리오가 유지되는가.
- **다이어리/포토부스**: 테마·스티커 자산이 깨지지 않고, 폰트(`NeoDunggeunmo`)와 디자인 토큰 일관성이 유지되는가.

## 보안·환경

- `.env*` 값이 로그·diff·스크린샷에 노출되지 않는지 확인.
- 새로 추가된 `EXPO_PUBLIC_*`이 민감 값이라면 BM/백엔드 가이드와 함께 검토를 요청한다.

## 보고 양식

- 통과/실패를 명확히 구분하고, 실패는 **재현 절차 + 기대값/실제값**으로 정리한다.
- 추측한 부분은 "확인 안 됨"으로 표시한다. 통과로 일반화하지 않는다.
